# Renatka — change history and porting notes

This file exists so a future version of ClioPlay can be re-branded and re-fitted
to this car without repeating the discovery work. It records **what was changed,
why, and the hardware facts that were learned the hard way**.

If you are an AI model picking this up: read §3 before touching anything. Most
of the surprises were in the car, not in the code.

- **Upstream base:** `pxwel-dev/ClioPlay` commit `7a962e2` (upstream says `2.0.0`)
- **Renatka version:** `2.2.0` (`src/VERSION`), versioned independently of upstream
- **Target car:** Renault Scénic III (2010), Carminat TomTom non-LIVE,
  `hw_remote=0`, `hw_handsfree=0`, `hw_bluetooth=1`, Linux 2.6.13 / S3C2443
- **Fork:** `https://github.com/bobczan/Renatka`
- **Card:** 4 GB SDHC, FAT32, label `SCENIC` (upstream asks for 8 GB; 4 GB is
  enough for a single-county test bundle, ~105 MB).

## 1. Why the Renatka tree was rebased

The old Renatka tree was a 1.x-era fork. ClioPlay 2.0 replaced the header and
footer with the HUD pill system, so most of the old UI patches no longer apply.
The full 2.0 tree was taken and only the still-relevant changes were re-applied.

**Not ported on purpose:** the 28 px top bar, reordered bottom bar, larger clock
and the old bottom strip — 2.0's HUD supersedes all of them.

## 3. Hardware facts learned on the car

### 3.1 Card mount point — the first boot failure

Upstream `ttn` assumes `SD=/mnt/sdcard`. **On this firmware there is no
`/mnt/sdcard`; the card is mounted at `/media/sdcard`.** With the wrong path
every binary lookup fails, `exec` never happens, and the unit falls through to
the stock TomTom app (old Carminat logo, "no map loaded").

`ttn` now probes `/proc/mounts` and a candidate list, then picks the directory
that contains `clio843/clio040`. `bootdiag.txt` in the card root records the
result of every boot.

### 3.2 The unit itself

From the factory card's own `LOGGING/SWLLOG0.LOG`:

```
Device Name  = Carminat TomTom
Device Unique ID = AK6ZE BSH9N
Device Serial = IA6400J00303
Bootloader version = 80055
Device Version = 542199   VersionVersion = 8842
CheckSwVersion(Downgrade major version not possible! (8842->8841))
Start(Startup failed. retVal = 19)
```

So the unit runs **firmware 8.842 from internal memory**, and the factory card's
own installer image was 8.841 — an illegal downgrade, which is why that card's
TomTom install was dead. The unit also creates `loopdir/loopback.ex3` (15 MB)
on its own at boot; it does not need to be provided.

### 3.3 The two vendor files

`tools/prepare_vendor.py` downloads
`navcore_8843.3130258.Carminat_TomTom.cab` (24.7 MB, SHA-256 pinned) and takes
two files from **`install/DS_1/IA0000700006swlimage0.zip` inside the CAB**:

| File | Role |
| --- | --- |
| `ttsystem` | TomTom system image the unit executes at boot (TTAB4 container) |
| `vehicledaemon` | vehicle daemon; restarted by `ttn` after `focusd` replaces the Focus endpoint |

They are proprietary and are not in the repository. Nothing else from TomTom is
used — no maps, no navigator, no UI.

### 3.4 Armrest console FIFO — the second boot failure

Records arrive as 28-byte frames on `/dev/input/CswEvent0`. Two non-obvious
rules:

1. **The consumer creates the node.** `vehicledaemon` opens it for writing, but
   nothing creates it unless the stock navigator does. The old helper `cswd`
   did `unlink` + `mknod(path, S_IFIFO|0666)`, and `clio040` now does the same
   in `csw_init()` (treating `EEXIST` as fine). Without this the FIFO simply
   never exists and no control is ever seen.
2. **The record shapes differ per control**, and most fields are garbage for
   buttons:

| Control | `src` | `dir` | `rot` | Notes |
| --- | --- | --- | --- | --- |
| Console button | 1…9 | 2 or 5 (not meaningful) | uninitialised | key by `src` alone |
| Joystick | 0 | 1 up, 2 down, 3 right, 4 left | 3 | |
| Knob rotation | 0 | 5 | 1 anticlockwise, 2 clockwise | both positive; sign means nothing |
| Knob press | 0 | 5 | 3 | the same record repeats for seconds while held; one key per burst (1.2 s guard) |

Field order, 7 × little-endian `u32`: `source, direction, rotation, pressed,
duration, steps, unnamed`.

Recovered `src` → key mapping (Linux input codes):

| Control | `src` | Key | Renatka action |
| --- | --- | --- | --- |
| top-left soft key | 1 | 1 `ESC` | zoom out / delete char |
| back | 2 | 13 `EQUAL` | back |
| top-right soft key | 3 | 14 `BACKSPACE` | zoom in / next field |
| info | 4 | 28 `ENTER` | ETA |
| menu | 5 | 68 `F10` | menu |
| light | 6 | — | ignored |
| repeat | 7 | — | ignored |
| dest | 8 | 193 `F23` (old build) → mapped to menu here | menu |
| map | 9 | 67 `F9` | map |

The built-in defaults live in `csw_defaults()`; `cswmap.ini` on the card
overrides them (`btnN=`, `dirN=`, `rot1=`, `rot2=`, `push=`, or the generic
`src=/dir=/act=`).

### 3.5 Outside temperature — still missing

`poll_cltemp()` reads a plain integer from `/tmp/cltemp`. Nothing writes it
yet. The value lives on the PAC reflection socket (port 3700, `VehicleStatus`
interface 37, item 4, `-1024` = unknown).

The owner's older card contains a working `vstatd` (ARM, static, ~3.6 KB) that
binds ports 3400/3401/3700/3800/4000/4001/5600/5700, reads `/var/run/PAC` and
writes `/tmp/cltemp`. Its log showed `STATUS id=4 value=14` (14 °C). It was
**not** shipped in this build (buttons first); reusing it is the shortest path
to temperature, or write an equivalent from source.

## 4. The CSW reader in `clio040.c`

| Function | Job |
| --- | --- |
| `csw_init()` | reads the `csw` marker, creates the FIFO, truncates an oversized log, loads the map |
| `poll_csw()` | non-blocking open (retry 1 s), 28-byte framing, live map reload every 5 s |
| `csw_record()` | per-shape decode + debounce |
| `csw_map_line()` / `csw_map_load()` / `csw_defaults()` | `cswmap.ini` parsing and built-in defaults |
| `csw_log()` | **Debug-only**; no card writes in normal use |

Enabled by an empty file `csw` in the card root. With Debug off the FIFO is
still created and read; deleting `csw` disables the whole path.

## 5. HUD changes

- Speed card is bottom-right, manoeuvre card bottom-left.
- The speed pill's width is **measured from the digits** (`width(title,3)`), so
  there is no empty area when no limit is known.
- Speed digits are face 3 (10×11, same size as the clock). To make them larger,
  change the `3` in `width(speed.title,3)` and `compact_center(...,3,...)`.
- Limit sign: three filled discs — white `r=22`, red `r=21`, white `r=15` — then
  black digits at face 4 (or smaller if the text is wide). Estimated limits use
  a grey ring. `INF`/`VAR`/unknown draws nothing.
- Bar height is `HUD_BAR_H=49` with `HUD_BOTTOM_Y=214`, keeping the bottom edge
  at 263 px.

## 6. Build and install

### 6.1 Binaries

```sh
cd src
python3 tools/build_ui.py --install
```

Ends with `ValueError: Preview input changed; run tools/render_previews.py` —
**cosmetic**. The binaries are installed before that check, and `install.py`
never reads `latest.json` / `SHA256SUMS`.

Current hashes: `clio040 162f2e29…`, `cliospl 97f184dd…`, `clioa2dp b9f52624…`.

### 6.2 Navigation bundle — must run on ext4

On a `/mnt/c` DrvFs mount, `os.replace()` of a SQLite file that is still open
(as `build_index()` in `build_ocean.py` leaves it) **silently leaves the target
missing**, and the build dies with:

```
sqlite3.OperationalError: unable to open database file
```

Build with `--work` and `--output` under `/home/...`. The coastline cache may
stay on `/mnt/c` because it is read-only after the first extraction.

```sh
python3 navigation-builder/build_navigation.py region.osm.pbf --yes \
  --output /home/pc/clioplay-nav/output \
  --work   /home/pc/clioplay-nav/work \
  --cache  /mnt/c/.../navigation-builder/.cache
```

Geofabrik moved GB: use `…/europe/united-kingdom/england/<county>-latest.osm.pbf`.
Northamptonshire is 23 MB and builds in a few minutes.

### 6.3 Card

WSL does not auto-mount the reader:

```sh
mount -t drvfs G: /mnt/g -o uid=1000,gid=1000,umask=022
```

Then `tools/prepare_card.py` → `navigation-builder/tools/install_nav.py` (the
scripts in `C:\Users\PC\opencode\scripts` do this end to end).

Card layout:

```
ttn  ttsystem  vehicledaemon        boot + vendor runtime
clio843/                            clio040 cliospl clioa2dp font.bin btstart.sh
                                    focusd hidd prefs.ini card-runtime.json
clio843/maps/                       map.cpm route.cpr route.qadj fonts.cpf
                                    regions.cpg timezones.cpt cameras.cpc build.json
csw                                 empty marker: armrest reader on
cswmap.example.ini                  template, inactive unless copied to cswmap.ini
loopdir/loopback.ex3                created by the unit itself
```

### Fresh-clone check

Verified from a clean clone of `https://github.com/bobczan/Renatka` (2.1.1):

```sh
git clone https://github.com/bobczan/Renatka.git
cd Renatka/src
python3 tools/prepare_card.py /tmp/runtime     # fetches and verifies the CAB
python3 tools/build_ui.py --install            # rebuilds the binaries
```

- `prepare_card.py` succeeds and produces the 11-file runtime.
- `build_ui.py` rebuilds **bit-for-bit identical** binaries: `clio040 60361bcf…`,
  `cliospl 97f184dd…`, `clioa2dp b9f52624…`. The committed binaries and the
  committed source agree.
- `build_ui.py --install` still ends with the cosmetic `Preview input changed`
  error after installing, as documented in `RENATKA.md` §4.

`src/build-reports/*.json` must always match the committed binaries: a fresh
clone has no `build/` directory, so `prepare_card.py` verifies against those
reports. They are regenerated by copying `src/build/*.build.json` after a build.

### What is not in the repository

| Excluded | Why | How to get it |
| --- | --- | --- |
| Navigation maps (map/route tiles, atlas packs) | generated data, several GB | build from an `.osm.pbf` with `navigation-builder/`, or copy a working `clio843/maps` |
| `ttsystem`, `vehicledaemon` | proprietary TomTom firmware | `tools/prepare_vendor.py` downloads the pinned CAB |
| `SHA256SUMS`, `latest.json` | release metadata produced by `refresh_latest.py` | present but **stale** in this fork; neither the build nor `install.py` reads them |

A clone therefore contains the program, not a ready-to-drive card.

### Updating the runtime without destroying the maps

`install_nav.py` treats the map bundle as replaceable: files listed in the old
`build.json` but not in the new one are moved into a `clioplay-backup-*` folder
before the new bundle is written. Installing a runtime update together with the
Northamptonshire test bundle therefore moves an atlas out of `clio843/maps` —
and on a nearly full card there is no room to put it back.

For a runtime-only update, copy just these and leave `clio843/maps`,
`prefs.ini`, `csw`, `cswmap.ini` and the `.dat` files alone:

```
ttn  ttsystem  vehicledaemon
clio843/clio040  cliospl  clioa2dp  btstart.sh  focusd  hidd  font.bin
clio843/card-runtime.json
```

`C:\Users\PC\opencode\scripts\update_runtime.sh` does exactly this.

## 7. Logging and card writes

`debug=0` is the shipping default. With it off, no `state.log`, `key.log`,
`focus.log`, `bt.log` or `csw.log` is written and nothing polls the card.

`debug=1` in `clio843/prefs.ini` enables all of them, including a per-record
`csw.log`. `ttn` clears logs at boot except `csw.log`, so armrest captures
survive a restart.

## 9. Porting to a new ClioPlay release

1. Fetch upstream and pick the new base commit.
2. Create a working tree without `.git`, or branch from that commit.
3. Re-apply, in this order:
   1. `cliospl.c` splash title.
   2. Locale JSON key rename → regenerate `ui_translations.h`.
   3. `clio040.c`: `DRIVE_MAX_ZOOM`, `manualzoom` clamp, `poll_cltemp`,
      `MOD_ROUTE_POINT`, `HUD_BOTTOM_Y`.
   4. `hud.h`: corner swap, `HUD_BAR_H`/`HUD_LIMIT_R`, `hud_sign_text`,
      `hud_speed_sign`, measured speed width.
   5. `card-template/ttn`: card auto-detection + breadcrumbs; update
      `bootstrap-SHA256.json`.
   6. CSW block (`csw_*` functions, `s_mknod`, the two call sites in `run()`).
4. Rebuild, reinstall, and re-run the console/zoom/HUD checks.
5. If upstream changes the HUD box constants, re-check that `HUD_BAR_H`,
   `HUD_BOTTOM_Y` and the `road.box` offset still agree (bottom edge 263 px).
